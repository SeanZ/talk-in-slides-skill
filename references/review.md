# 评审清单

用法：跑完 `shoot.mjs`、lint 零错误之后，先看 `contact.png`，再逐张看每页截图（必要时看 `--all-steps` 每一步），逐条打勾。任何一条不过都要修，修完重新截图。

## A. 叙事（看 outline 和 contact.png）

- [ ] 只读每页标题，能复述整场论证；每个标题都是断言，不是名词短语。
- [ ] 有钩子（前 2 页内抛出问题或反常识）、有章节页分段、有收尾行动。
- [ ] 每页只有一个观点；没有"顺便再说一下"的内容。
- [ ] 数据都有来源或标注为示例；没有编造的数字、引语或客户名。

## B. 版面（逐页看图）

- [ ] 一眼能看出视线先落在哪里（唯一的焦点），第二眼看哪里也清楚。
- [ ] 标题位置全 deck 一致（同类页面锚点不跳）；左边线对齐。
- [ ] 留白有意图：不是"内容挤在上半部，下半部空着"，也不是塞满。
- [ ] 中文标题断行自然：不在词中间断，不出现孤字。
- [ ] 文字层级 ≤ 4 级（kicker / 标题 / 正文 / 注释），同级字号一致。
- [ ] 强调色每页 ≤ 2 处，且都指向结论；没有无意义的彩色。
- [ ] 卡片、柱子、节点等重复元素等宽等距；数值与图形比例正确。

## C. 图解与素材

- [ ] 图解画的是真实机制，删掉任何一个元素都会损失信息。
- [ ] 线宽、圆角、字号统一用 diagrams.md 的类；没有写死的 hex 颜色。
- [ ] 截图或录屏清晰，裁到只剩该看的部分；有 caption 告诉观众看哪里。
- [ ] 默认风格换成 `--theme night` 截一次图，所有元素依然可读（检验是否写死了颜色）；用了皮肤的 deck 换成另一种明暗（`--theme paper` 或 `night`）截一次。

## D. 动效（看 --all-steps）

- [ ] 每一步都揭示了新信息；没有"点一下什么也没变"或"一下出现三件事"。
- [ ] 入场顺序 = 阅读顺序；第 0 步的入场在约 1.2s 内完成。
- [ ] 讲过的内容被压暗或保持稳定，不会抢新内容的风头。
- [ ] 推近（data-cam）后构图完整，没有半截文字被裁。
- [ ] 每页动效类 ≤ 2 种；没有为动而动。

## E. 工程

- [ ] lint 零 ✗；剩余 ! 都有理由保留。
- [ ] 控制台无报错；所有图片和视频都能加载；视频有 webm 和 mp4。
- [ ] `<title>`、页眉页脚、署名、日期已经改成本 deck 的内容，示例文字一处不留（全文搜索"示例""你的名字""example"）。
- [ ] 每页有 `<aside class="notes">`，讲者能照着讲。
- [ ] 真实浏览器里按 M 进出总览、跨章节跳页都流畅；`custom.css` 里的过渡只涉及 `transform` 和 `opacity`。

## 质感标尺

拿不准的时候，用这三问对照：

1. **像不像杂志的一页？** 克制的字体、充足的留白、一个强调色、精确的对齐。
2. **像不像一部短片？** 镜头有方向，节奏有起伏，每一下点击都有理由。
3. **每样东西都是有意为之的吗？** 任何元素问"为什么在这里"都答得上来；答不上来就删掉。
