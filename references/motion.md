# 动效编排

动效是为叙事服务的：它控制观众**什么时候看什么**，而不是装饰。判断标准：去掉这个动效之后，观众会不会更难跟上？如果不会，就删掉。

## 状态模型

- 第 0 步是刚翻到这一页的状态。演讲者每点一下，步数加 1。
- 元素状态只由（页，步）决定：已经离开的页显示最终态，还没到的页是空的。后退、跳页、刷新、总览都能精确还原，所以不要用 JS 定时器去改 DOM。
- 翻页过程中，目标页的入场会自动推迟到镜头快落定时（`--arrive`），所以第 0 步的元素只需要写自己的相对延迟 `--d`。
- 退场永远没有延迟，一起消失。

## 一页的标准节奏

| 时刻          | 内容           | 写法                              |
| ------------- | -------------- | --------------------------------- |
| 0s            | kicker         | `rise`                            |
| +0.12–0.15s   | 标题           | `rise` `style="--d:.12s"`         |
| +0.28–0.35s   | 导语 / 正文    | `rise` `--d:.28s`                 |
| +0.3–0.5s     | 主视觉         | `zoom` / `pen` / `grow` `--d:.3s` |
| 点击 1、2、3… | 每次一个新信息 | `data-in="1"` 等                  |

- 一组并列元素用 `data-stagger`，间隔 80–140ms，不要手写一串延迟。
- 第 0 步的入场总时长控制在 1.2s 以内，否则讲者开口时画面还在动。

## 动效类怎么选

| 类                | 用于                                       | 别用于                                       |
| ----------------- | ------------------------------------------ | -------------------------------------------- |
| `rise`            | 默认的文字和卡片入场                       | —                                            |
| `fade`（不加类）  | 次要信息、注释                             | —                                            |
| `left` / `right`  | 与左右方向有关的内容（对照两侧、流程方向） | 普通文字                                     |
| `pop`             | 小而重要的东西：标签、徽章、手机框         | 大段文字                                     |
| `blur`            | 引语、断言页的那一句话：从模糊到清晰       | 一页内多处                                   |
| `zoom`            | 屏幕框、截图、大图                         | 文字                                         |
| `wipe`            | 横向展开的东西：进度条、高亮带、横幅       | 多行文字                                     |
| `pen`             | SVG 线描、箭头、折线、时间线轨道           | 填色块（填色块用 `.fill`，线描结束后才淡入） |
| `type`            | 一句"输入"感的短句：命令、提示词、搜索词   | 超过 40 字的句子                             |
| `grow` / `grow-x` | SVG 柱子和条形                             | HTML 元素                                    |

一页最多用 2 种动效类，整个 deck 的默认动效保持 `rise`。

## 分步揭示的手法

1. **累加**：新内容出现，旧内容保留（`data-in` 递增）。适合推导和清单。
2. **聚焦**：新内容出现时把讲过的压暗（`data-state="dim@2-4"`）。适合并列要点。**最后加一步把全部恢复**并给出收束句，否则总览和 PDF 里压暗的内容几乎看不见（lint 会报 `dim-final`）。示例见 steps 页。
3. **点亮**：所有内容都已出现，每一步只点亮一个（`data-state="lit@1-2"`，下一个用 `lit@2-3`）。适合解说一张图或一段代码。
4. **替换**：`data-in="1" data-out="2"` 和 `data-in="2"` 叠放在同一位置，可以做前后对比或数字更新。两个元素要用绝对定位叠在一起。
5. **划掉**：`.strike` 配合 `data-state="lit@2"`，用于推翻一个旧观点。
6. **推近**：`data-cam="0,0,1; 0,0,1; 400,120,1.7"`，在第 2 步把镜头推到图上某个细节（示例见 camera 页）。推近后的画面要构图完整，见下方"镜头"一节。

## 镜头

- 相邻页之间是平移，耗时约 1–1.5s；跨很多页跳转时镜头会自动"抬起再落下"，不需要你处理。
- `data-cam` 的 `dx,dy` 是相对页面中心的画布像素，`z` 是缩放倍数。推近程度建议 1.3–1.8 倍。超过 2 倍时 SVG 线条会显得太粗，文字也会糊。
- 怎么算 `dx,dy`：目标在页内的坐标 = 容器左上角 + viewBox 坐标 × （容器宽 ÷ viewBox 宽），再减去页面中心 (960, 540)。拿不准就在浏览器控制台里对目标元素运行 `el.getBoundingClientRect()`，除以舞台缩放比即可。推近后用 `--all-steps` 截图确认视野里没有大片空白。
- 推近时页眉页脚会自动隐藏。lint 的 `cam-crop` 会检查画面边缘有没有切到文字。
- **推近后不在画面里的元素，不要在推近那一步才出场**：观众看不到。推近那一步要揭示的说明，直接写在被推近的图里，比如 SVG 里的一段 `.d-text`。
- 不要每页都推近，整个 deck 用 1–3 次，留给真正需要细看的地方。
- 镜头飞行在浏览器合成线程上播放，缩放每变化 2 倍自动切段，这样拉远时不会按原尺寸栅格化整张画布。`DECK_HOOKS` 里不要碰 `#world` 和 `.frame` 的 `transform`、`left`、`top`，要动画自己的内容只改 `transform` 和 `opacity`。

## 总览（M）

- 当前页在屏幕上直线滑到自己的格位，其余页从长画布上滑进网格，离当前页越远起步越晚，镜头同时拉远；方向键、数字键或鼠标选页，Enter 飞入，Esc 返回。
- Enter 飞入另一页时落在它的**最终步**（缩略图里看到的那个画面，落地不闪）；Esc 或飞回当前页则回到原来的步，比它晚的元素淡出。
- 总览里每页显示的是**最终步**的状态，所以每页最后一步必须是完整、可读的画面（见上面"聚焦"手法的收束步）。
- 缩略图下的页名取页的 `id`，底部提示条显示完整标题：`id` 起短而有意义的英文词（`cover`、`merge`），没起 `id` 的页退回标题。
- 页数不限，但超过 30 页时总览缩略图会很小，考虑拆成两个 deck。

## 视频与实时内容

- `<video>` 到它出现的那一步自动从头播放，离开这一页就暂停并回到开头，不用写代码。
- 自定义内容（canvas 动画、实时图表）用 `window.DECK_HOOKS[页id] = { enter(step) {}, leave() {} }`。`enter` 每一步都会被调用，必须是幂等的。
